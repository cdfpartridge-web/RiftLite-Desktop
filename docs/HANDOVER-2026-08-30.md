## Released fix: stale Match Review must not block the next game

### Reported problem

A user on v0.9.65 could finish a game, see Home/Matches report a review waiting, and then be forced back to Matches with the message “Review the captured match before starting another game.” Restarting RiftLite cleared the condition. In at least one reproduction the health state said `review-needed` even though there was no real pending draft to review.

### Current fix

- `CaptureCoordinator.hasActiveMatchCapture()` no longer treats the durable `health.state === "review-needed"` flag as an active match.
- Provider switching still blocks genuine active capture, Atlas pending-end work, replay finalisation, and other unsafe transitions.
- The provider-switch message now asks the user to finish or stop the current match; it no longer demands completion of review.
- Renderer-level Play/Home redirects to Matches were removed.
- A real pending review still opens normally and remains visible in Matches/Home.
- The 900 ms pending-review fallback is generation-guarded. If capture health says review is needed but no pending draft exists, it calls `dismissMatchReview()` to clear the ghost state instead of trapping the user.

### Files/tests

- `src/main/services/captureCoordinator.ts`
- `src/renderer/App.tsx`
- `tests/captureCoordinator.test.ts`
- `tests/homeSurfaceIntegration.test.ts`

This fix is implemented, covered, and public in v0.9.71. An installed-build test across consecutive real games remains outstanding post-release and must not be represented as completed.

Key files:

- `src/shared/deckInsights.ts`
- `src/renderer/insightCardCatalog.ts`

Implemented views and statistics:

- Saved-deck selector with official card art hero, local record, win rate, streak, and a copyable text report.
- **Overview:** main-deck size, unique cards, average energy, opening-four probability of seeing a two-cost card, copy profile, copy-weighted energy curve, card-type distribution, recent rolling form, evidence coverage, and restrained callouts.
- **Card Usage:** mainboard and sideboard card art, played-when-observed percentage with exact denominator, keeps, unplayed observations, recycled/discarded observations, known-hand time, turn/outcome matrix, source-zone split, and sideboard gallery.
- **Matchups:** normalized opponent-legend records, format/season/initiative splits, observed battlefield results, and a data receipt explaining capture coverage.
- Filters for pre-season/current season, date range, opponent legend, and all linked versions versus the exact current deck snapshot.
- Default evidence scope uses pre-season plus current season and all available local history.

Accuracy and resource safeguards:

- Outcome claims use saved/completed local matches only.
- Duplicate card print rows are collapsed by canonical name and quantities are summed.
- Packaged card-registry art and costs are authoritative; snapshot data is a fallback.
- Current-list filtering uses the deck snapshot hash. Matches with no usable snapshot cannot be claimed as current-list evidence.
- Card/timing/source rows are restricted to identities in the current mainboard plus sideboard, preventing the chosen starting Champion from being treated as a normal played card.
- Combined replay parent IDs are included in evidence lookup.
- Stage filtering is disabled when manually combined games make preboard/post-board order unverifiable.
- Missing data is labelled as uncaptured/unknown, never treated as proof that an event did not occur.
- Timing and win-rate comparisons are labelled observational rather than causal.
- No Firebase reads are made.
- Raw replay enrichment starts only when Card Usage is opened, processes at most 64 uncached replays per pass with concurrency 2, persists a bounded localStorage cache, and exposes an **Analyze older** action for more.
